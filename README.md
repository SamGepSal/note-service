# Сервис заметок

Учебный проект по курсу «Инфраструктура и администрирование».

Сервис позволяет создавать заметки, просматривать их список
и получать отдельную заметку по номеру. Предназначен для хранения
коротких текстовых записей во время работы приложения.

## Возможности

- POST /notes — создать заметку.
- GET /notes — получить список заметок.
- GET /notes/{note_id} — получить заметку по номеру.
- GET /health — проверить работоспособность.
- GET /version — узнать версию приложения.

Несуществующий номер возвращает ошибку 404.
Некорректный формат номера возвращает ошибку 422.

## Ограничения

Заметки хранятся в памяти процесса.
Добавленные через API заметки исчезают после остановки
или автоматического перезапуска приложения.

## Установка

Нужны Python 3.14 и Git.
Команды ниже предназначены для macOS и Linux.

```bash
git clone https://github.com/SamGepSal/notes-service.git
cd notes-service
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

## Настройки

APP_NAME — название приложения.
По умолчанию используется «Сервис заметок».

Задать название перед запуском:

```bash
export APP_NAME="Мои учебные заметки"
```

Файл .env.example содержит пример настройки.
Приложение не загружает этот файл автоматически.
Настройка передаётся через окружение терминала.

## Запуск

Обычный запуск:

```bash
python -m uvicorn app_final:app --host 127.0.0.1 --port 8000
```

Для разработки с автоматическим перезапуском при изменении кода:

```bash
python -m uvicorn app_final:app --reload
```

Документация и форма для отправки запросов:
http://127.0.0.1:8000/docs

Для остановки сервера нажмите Ctrl+C.

## Проверка работоспособности

При работающем сервере выполните в другом терминале:

```bash
curl http://127.0.0.1:8000/health
curl http://127.0.0.1:8000/version
```

Ожидаемые ответы:

- /health — {"status":"ok"}
- /version — {"version":"0.1.0"}

## Автоматические тесты

В активированном окружении установите зависимости для разработки:

```bash
python -m pip install -r requirements-dev.txt
```

Запустите тесты:

```bash
python -m pytest -v
```

Проверяются работоспособность, создание заметки и её появление
в списке, поиск по номеру, отсутствующая заметка и неверный
формат номера.

## Логи и диагностика

Логи выводятся в терминал, где запущен сервер.
В них видны запросы, создание заметок и обращения
к отсутствующим заметкам.

Если приложение не работает:

- No module named ... — проверьте, активно ли .venv
  и установлены ли зависимости.
- Address already in use — остановите ранее запущенный
  экземпляр сервера или выберите другой порт.
- Connection refused — проверьте, запущен ли сервер
  и правильно ли указан адрес.
- 500 Internal Server Error — посмотрите traceback
  в терминале сервера.
- 404 на главной странице / — ожидаемый результат:
  в проекте нет обработчика этого адреса.
  Для проверки используйте /health или /docs.

## GitHub Actions

Workflow находится в .github/workflows/ci.yml.

При push и pull request GitHub запускает тесты на Ubuntu.
После успешных тестов создаётся artifact notes-service
с файлами приложения, зависимостями и README.

Архив доступен на странице запуска во вкладке Actions
и хранится 30 дней.
